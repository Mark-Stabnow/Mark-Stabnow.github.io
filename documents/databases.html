CS 499 · Enhancement Three

Databases

The Android version used SQLite for accounts and inventory. Quantity updates replaced the current count and the upgrade path could drop existing tables. The database enhancement focused on moving the original inventory data forward without pretending the Android app had history it never stored.

Import and preservation

A Python exporter reads inventory records from the Android database without exporting usernames or password hashes. A Node importer validates the exported file before saving anything. It reports missing fields, invalid quantities, and duplicate SKUs for review. The import keeps the original item IDs linked to the new records and preserves the original timestamp text because the Android timestamps do not include a timezone.

Category and reorder level are supplied during import because the original Android database did not contain those fields. Each imported item receives an opening count. Earlier stock adjustments cannot be reconstructed because the original application did not save them.

Migration and reconciliation

The database changes are added in a second SQL migration so the first migration remains intact. The enhancement adds source provenance, constraints, indexes, and a reconciliation view. The view compares the stored quantity with the total from stock history and flags disagreements for review instead of changing the quantity automatically. A zero opening count and a missing history record are handled as different conditions.

Verification status

The preparation record reports 99 named dependency free automated tests passed with 0 failed and 0 skipped. It includes a real SQLite to JSON to Node pipeline for exactly 1,000 items, exporter tests, source preservation checks, and the algorithm benchmark.

The same record says the environment did not have PostgreSQL, Docker, pg_dump, pg_restore, or the remaining build dependencies. The full TypeScript build, PostgreSQL integration suites, migration and restore checks, SQL query timing, and Chromium browser regression suite were not run there. I am keeping those items marked as not run rather than treating them as passing evidence.
