CS 499 · Enhancement One

Software design and engineering

The artifact started as an Android application where screen classes handled several jobs at once: form checks, database calls, filtering, and drawing inventory cards. For the software design enhancement I rebuilt the workflow as a progressive web application using React and TypeScript, an Express API, and PostgreSQL.

Separation of responsibilities

The React client handles screens and form state. Separate client modules handle API calls, cached inventory, and queued stock changes. On the server, routes check the session and role before passing validated requests to repository code. The repository owns database access and transactions. This gives each part a smaller responsibility and makes it easier to test the behavior without depending on the screen code.

Security and roles

The enhanced project uses manager, clerk, and viewer roles. Managers can add, edit, archive, and adjust stock. Clerks can record stock changes. Viewers can read inventory and history. Those limits are enforced at the API rather than only by hiding buttons. Passwords use salted scrypt. The implementation also includes account lockout, login request limits, session cookies, and checks against cross site write requests.

Offline stock changes

Offline stock changes are stored in a local queue with stable request IDs. The interface keeps pending changes separate from the confirmed count. When the connection returns, the server checks the request before saving it. Reusing the same request ID prevents a retry from applying the same stock change twice.

The design intentionally does not copy every Android feature. Adding or editing item metadata still requires a connection, the PWA uses in app stock indicators instead of the original text message feature, and the demo uses seeded accounts instead of public registration.
